# 팀 리뷰 기준

이것은 독립적인 구현 작업이 아니라 검토 중 적용하는 기준이다.

- 원래 요구와 현재 변경의 관계를 확인한다.
- 지적에는 파일·위치와 이유를 포함한다.
- 테스트를 실행한 증거가 없으면 ‘미실행’으로 표시한다.
- 원문에 없는 요구를 만들어 결함이라고 주장하지 않는다.
- 문서가 다르다면 코드·승인된 요구·문서 각각의 근거를 구분한다.
- 확정된 문제, 추가 확인, 취향에 가까운 제안을 구분한다.
- 근거 있는 문제가 없으면 그 사실을 보고한다.
- 검토 요청만으로 파일을 수정하지 않는다.

이 스킬은 관련 요청에서 선택될 수 있지만 자동 호출을 보장하지 않는다.
실습에서는 실제 Skill 호출 또는 읽기 기록을 확인한다.
