# 공통 기준 카드

확인일: 2026-10-04. 아래는 공식 자료를 짧게 요약한 교육용 카드다.
모든 항목을 모든 요청에 적용하는 양식이 아니다.

## C1. 목표·제약을 명확하게 전달
필요한 산출물, 형식, 작업 범위를 분명히 한다. 이미 입력에 충분한 정보가 있으면 반복해서 추가하지 않는다.
근거: Prompting best practices / Be clear and direct.
https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices

## C2. 목적에 필요한 맥락
모델이 알 수 없는 목적이나 배경이 결과를 바꾼다면 제공한다. 실행자가 스스로 찾을 수 있는 모든 사실을 미리 질문할 필요는 없다.
근거: 같은 문서 / Add context to improve performance.

## C3. 예시와 구조는 필요할 때
복잡한 형식·판단을 전달할 때 예시와 구분된 구조를 쓸 수 있다. 단순 질문을 무조건 장문·XML로 바꾸라는 뜻은 아니다.
근거: 같은 문서 / Use examples; Structure prompts with XML tags.

## C4. 성공 기준과 실제 결과를 구분
무엇이 성공인지 먼저 정의하고 결과로 확인한다. 프롬프트 변경만으로 모든 모델·도구 문제를 해결할 수는 없다.
근거: Prompt engineering overview / Before prompt engineering.
https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/overview

## 편집 원칙
원래 의도와 제약을 보존하고, 없는 사실을 만들어 넣지 않는 것은 이 교육용 코치의 계약이다.
‘몇 점짜리 프롬프트’라는 근거 없는 총점을 부여하지 않는다.
