# 강사 운영 안내

## 수업 전

- 참가자가 사용하는 실행기에서 Claude Code 2.1.283 이상과 인증 상태를 확인합니다.
- 세 랩은 각각 새 작업 공간에서 시작합니다. 기존 작업을 삭제하거나 덮어쓰지 않습니다.
- Lab 2의 공용 API 주소·토큰 또는 로컬 대체를 준비합니다. 토큰은 Claude에 붙여넣지 않습니다.
- 스킬 파일은 Claude 동작을 바꾸는 자료이므로 환경에 따라 개별 쓰기 승인이 필요합니다.
- 강사용 실제 응답·사용량 상세·토큰·원본 교안은 공개 저장소에 올리지 않습니다.

## 코치 진행

참가자가 기준과 예측을 정한 뒤 제작·실행을 요청합니다. 이미 준 결정은 다시 묻지 않습니다.
가이드 시작이나 힌트 요청만으로 과제를 완성하지 않게 하고, 원문과 실제 결과를 비교합니다.
참가자가 결과를 확인했다고 대신 기록하지 않습니다.

## Lab 1 관찰 포인트

- 길 A도 양식과 판단 기준을 실제로 바꿔야 합니다. 시작본 실행만으로 완료 처리하지 않습니다.
- 길 B는 선택한 업무를 새 스킬로 구현합니다.
- 미정 값, 계획과 완료의 구분, 날짜를 해석할 수 있는 문맥을 함께 봅니다.
- 첫 결과에 문제가 있으면 기준을 수정하고 새 세션에서 다시 호출합니다.

## Lab 2 관찰 포인트

- 공통 클라이언트는 HTTP와 인증만 담당합니다. 업무 절차를 참가자 스킬에 구성합니다.
- 상신 전 조회, 사용자 확인, POST, 생성된 ID로 재조회가 실제로 있었는지 확인합니다.
- 필수 조회의 권한 거부·통신·해석 오류를 과거 예측값으로 대신하지 않습니다.
- `pending`을 승인 완료로 표현하지 않습니다.
- 중복과 응답 불확실 상황에서는 보존한 request_key를 사용합니다.
- 서버의 최종 검사와 스킬의 사전 판단은 서로 다른 역할입니다.

## Lab 3 관찰 포인트

- prompt-coach는 제공 도구이며 이 랩에서 새로 만드는 대상이 아닙니다.
- 좋은 결과의 기준을 먼저 정하고, 코치가 쓴 문장만 보고 개선을 확정하지 않습니다.
- 표 형식은 맞아도 사실 판정이 틀릴 수 있습니다. 원문과 비교해 다시 수정합니다.
- 개선본이 더 길거나 더 비쌀 수 있습니다. 품질과 비용을 함께 판단합니다.
- 비교 도구는 같은 모델·입력·도구·effort로 실행하며, 기본 effort는 medium입니다.
- 실패한 실행이나 다른 모델의 결과를 유효한 비용 비교로 표시하지 않습니다.
- CLI 추정 비용과 실제 청구액, 코치 비용과 이후 업무 비용을 구분합니다.
- 공유용 README·지시문을 확인하고, artifacts·measurements·토큰을 커밋하지 않습니다.

## 리허설 해석

검증은 가상 참가자의 명시적 요청을 실제 Claude에 전달한 시나리오입니다.
비대화형 실행의 파일 쓰기 승인은 공식 SDK 승인 응답 절차로 처리했습니다.
승인 검토 대기가 포함된 시간을 실제 강의 소요 시간으로 사용하지 않습니다.
모델 응답의 확률적 성격 때문에 워크시트와 실제 실행 증거를 사람이 확인해야 합니다.
